# План нового клиента для Silo (рабочий документ)

Статус: **обсуждение**. Решения помечены как `[решено]`, открытые вопросы — `[открыто]`.

## 1. Общая идея

- Клиент — нативное Android-приложение для телефонов, планшетов и Android TV.
- Клиент умеет: скачать сервер Silo, запустить его локально, подключиться к удалённому серверу, управлять сервером через API.
- Интерфейс клиента — **свой нативный** (не веб-интерфейс Silo).
- Страницы **плагинов** Silo показываются через **WebView** (внутри нативного экрана).
- `[решено]` Веб-интерфейс Silo (главный экран, админка) клиентом **не используется** — экраны рисуем сами через API.

## 2. Адрес сервера и локальный режим

- `[решено]` Адрес сервера хранится в настройках (как в старом клиенте, ключ `host`).
- `[решено]` Локальный сервер — `http://127.0.0.1:<port>` (порт из конфига Silo, по умолчанию 8090).
- `[решено]` Удалённый сервер — любой другой адрес, введённый пользователем; список сохранённых серверов хранится отдельно.
- `[решено]` Запуск локального сервера — в отдельном **сервисе** (foreground service), как `TorrService` в старой версии.
- `[решено]` Работа с сервером — только через API; клиент не лезет во внутренности Silo.

Справка по старой версии (ветка `master`):
- `settings/Settings.kt`: `host` (по умолчанию `http://localhost:8090`), `saved_hosts` (сохранённые серверы).
- `server/local/TorrService.kt`: локальный сервер как foreground-сервис, старт/стоп через `Intent`.
- `app/Consts.kt`: адреса загрузки сервера и приложения (`releases.yourok.ru`) — для Silo источник загрузки будет другим.

## 3. Экраны и последовательность запуска

### 3.1 Splash (первый экран)
- Анимация.
- Проверка: есть ли сохранённый адрес сервера в настройках.
  - **Есть** → подключаемся к нему (см. 3.2 / 4).
  - **Нет** → автоматически скачиваем сервер с GitHub (источник пока не готов, добавится позже) → переход к онбордингу (3.3).

### 3.2 Подключение к сохранённому серверу
- Если адрес `127.0.0.1` → проверяем, запущен ли локальный сервис; если нет — запускаем.
- Если удалённый адрес → пингуем `/api/system/ping`.
- Ошибка подключения → экран «Сервер недоступен» с действиями: повторить, изменить адрес, выбрать другой сервер.

### 3.3 Онбординг (чистый запуск, сервер скачан, настроек нет)
- Экран выбора режима работы:
  - **Одиночный** — без пароля owner, сразу на главный экран.
  - **Многопользовательский** — ввод пароля для owner, затем вход под owner.
- `[решено]` Режим определяется наличием пароля owner в конфиге сервера (пустой пароль = открытый/одиночный режим, как в Silo `auth.owner_password`).

### 3.4 Главный экран
- Нативный экран библиотеки/торрентов через API.
- Плагины — пункты меню, открываются в экране с WebView.

## 4. Выбор пользователя при повторном запуске (ОТКРЫТО)

Сценарий: настройки уже есть, сервер выбран, в многопользовательском режиме.

Варианты:

**A. Всегда экран входа (логин + пароль).**
Плюс: безопасно. Минус: неудобно, если пользователь один на устройстве.

**B. Список профилей на устройстве (как «выбор аккаунта»/Netflix).**
Плюс: быстрый выбор. Минус: нужно хранить токены.

**C. Запомненный токен + выбор профиля, пароль только при первом входе на устройстве.**
Токен API хранится в защищённом хранилище (Android Keystore / EncryptedSharedPreferences). Пароль просим, только если токен истёк или отозван.
Плюс: удобно и безопасно. Минус: сложнее реализация, зависит от срока жизни токена в Silo.

`[предложение]` Вариант **C**: при первом входе на устройство — логин/пароль, дальше — выбор профиля из списка на устройстве без повторного ввода пароля, пока токен валиден. Если токен отозван → запрос пароля.

Нужно уточнить: как долго живёт токен в Silo и есть ли механизм обновления/отзыва (см. `internal/user/service.go`, `Authenticate`, `Login`).

### 4.1 Решения по выбору пользователя (подтверждено)
- `[решено]` Вариант C: токен пользователя сохраняется после входа; повторно пароль не спрашиваем, пока токен валиден.
- `[решено]` Токен можно сменить самостоятельно на сервере — если токен перестал работать, клиент просит пароль заново.
- `[решено]` Хранится **список токенов всех вошедших на устройство пользователей** (домашний сервер, все доверяют друг другу).
- `[решено]` При выходе пользователя его токен удаляется из списка.
- `[решено]` Токены хранятся в обычных настройках (SharedPreferences), без шифрования — по решению владельца.
- `[решено]` Экран «Сменить пользователя» в меню: показывает список сохранённых профилей, позволяет войти под другим аккаунтом.
- `[решено]` Минимальный Android API и устройства — по согласованию (телефон, планшет, ТВ; конкретный API уточним при старте реализации).

> Замечание для реализации: хранение токенов в открытых SharedPreferences означает, что любой, кто получит доступ к файлам приложения (например, на рутованном устройстве), получит доступ к аккаунтам. Решено принять это для домашнего сервера; при желании позже можно перейти на EncryptedSharedPreferences без изменения логики.

## 4.2 Запуск сервера на устройстве (решено)

- `[решено]` Как в старом клиенте: бинарник Silo скачивается в `filesDir`, получает `setExecutable(true)` и запускается через **libsu** (`Shell.Builder`), в foreground-сервисе `TorrService`.
- `[решено]` `targetSdk` = **28** (как в старом клиенте). Причина: ограничение exec из `app_data` для `targetSdk ≥ 29` в этом случае не действует.
- `[решено]` Публикация в Google Play **не планируется**. Если перестанет работать на новых версиях Android — решим тогда (варианты: `nativeLibraryDir` / `jniLibs` с `targetSdk` 34+).
- `[решено]` Версия libsu: `3.2.1` (как в старом клиенте; в новых версиях запуск через shell работал хуже).
- `[решено]` Репозиторий libsu: JitPack (`settings.gradle`).

### 4.3 Внесённые изменения в проект (ветка `silo`)
- `app/build.gradle`: `targetSdk 28` (был 37), добавлена `com.github.topjohnwu.libsu:core:3.2.1`.
- `settings.gradle`: добавлен репозиторий JitPack.
- `AndroidManifest.xml`: INTERNET, ACCESS_NETWORK_STATE, FOREGROUND_SERVICE (+DATA_SYNC, MEDIA_PLAYBACK), POST_NOTIFICATIONS, объявлен сервис `.server.local.TorrService` (dataSync|mediaPlayback).
- Класс `TorrService` ещё не создан — будет в следующем шаге.
- `[открыто]` Источник загрузки бинарника Silo (GitHub release / asset, архитектуры `arm64-v8a`, `armeabi-v7a`, `x86_64`, `x86`) — будет готов позже.

## 4.4 Открытие магнет-ссылок из других приложений (на заметку, не реализовано)

Сценарий: пользователь ищет фильм в NUM, нажимает на торрент, открывается magnet-ссылка, система предлагает приложения. Клиент должен перехватывать `magnet:` и добавлять торрент на сервер.

- `[решено]` Клиент регистрирует intent-filter на `magnet:` (схема `magnet`), как старый TorrServe — TorrServe должен быть в списке приложений по умолчанию для magnet.
- `[решено]` Магнет добавляется на сервер через API (`POST /api/torrents`) для **текущего активного пользователя**.
- `[решено]` **Одиночный режим / без пароля** — работаем как с единственным пользователем, без выбора.
- `[решено]` **Многопользовательский режим, один вошедший пользователь** — магнет уходит ему по умолчанию.
- `[решено]` **Несколько вошедших пользователей** — при открытии магнета показываем список зашедших на устройстве пользователей и даём выбрать, кому добавить. Запоминаем последний выбор как вариант по умолчанию (для быстрого добавления).
- `[открыто]` Нужно уточнить: показывать ли диалог выбора каждый раз или только при первом открытии магнета.
- `[открыто]` Что делать, если выбранный пользователь не вошёл (токен отозван): попросить пароль и обновить токен.

## 6.1 Текущий статус рабочей версии (для тестирования)

Готово и проверено на эмуляторе (Android 9 / Android TV):
- Splash → запуск локального сервера (`TorrService`) → ping.

- Сквозной ввод пароля owner через UI на эмуляторе не проверен (автоматизация ввода нестабильна).

## 7. Журнал решений
- Клиент пишется с нуля в ветке `silo` (orphan).
- Интерфейс: нативный; плагины — WebView.
- Адрес сервера в настройках; локальный сервер в foreground-сервисе.
- Онбординг: при чистом запуске выбор одиночный/многопользовательский.
- Запуск сервера: как в старом клиенте (бинарник в `filesDir`, libsu, `targetSdk` 28), без публикации в Play.
- Выбор пользователя: вариант C; список токенов всех вошедших пользователей хранится в обычных настройках; выход удаляет токен; экран «Сменить пользователя» в меню.

## 8. Реализованный интерфейс (v2, фрагменты)

Единая `MainActivity` + постоянная боковая панель (ТВ/планшет - с подписями, телефон - иконки).
Экраны - фрагменты, заменяют прежние отдельные Activity.

- `TorrentsFragment` - сетка карточек: постер 2:3, бейдж статуса, размер, пиры; поиск, автообновление (3 с) без потери фокуса.
- `TorrentDetailFragment` - постер, статус (размер, пиры, сиды, файлы), «Смотреть», «Удалить торрент», список файлов (тап - плеер, долгий тап - просмотрено).
- `SettingsFragment` - адрес сервера, «Локальный», скачивание сервера с yourok.ru/share, «Запустить»/«Остановить», выход из аккаунтов.
- `UsersFragment` - сессии на устройстве: выбор активного, выход, вход под другим.
- `AddTorrentDialog` - magnet/hash из буфера; при нескольких пользователях - выбор, от чьего имени.
- `MagnetActivity` - перехват `magnet:` из других приложений.

Технические решения:
- Сессии хранятся **отдельно для каждого адреса сервера** (у локального и удалённого серверов разные токены).
- Пустой токен = открытый сервер без пароля: запросы без `Authorization`.
- Cleartext HTTP разрешён (домашняя сеть), см. `network_security_config.xml`.
- Фокус на ТВ: карточки focusable с янтарной рамкой, при входе на экран фокус ставится на первую карточку.

Проверено на приставке (Android 14, armeabi-v7a):
- список торрентов с удалённого сервера и с локального; карточки, бейджи, постеры;
- вход owner, смена активного пользователя, выход;
- добавление magnet вручную и через intent из другого приложения;
- удаление торрента; открытие потока во внешнем плеере (системный выбор);
- скачивание сервера из приложения и его запуск; остановка и повторный запуск сервера.

## 9. Итерация 2: SSE, плагины, плитки, поиск сервера

- **SSE вместо опроса.** Клиент подписывается на `GET /api/events` и получает только изменения:
  `sync` (полный список), `card` (изменённая карточка), `remove`. Опрос раз в 3 с убран,
  поэтому плитки не мигают и не переставляются (проверено: два скриншота через 6 с совпадают побайтно).
- **Плитки как в вебе.** Фон прозрачный, плитка «выступает» (подложка, рамка, тень) при наведении
  мыши и при фокусе с пульта.
- **Плагины.** Секция «ПЛАГИНЫ» в боковом меню заполняется из `GET /api/ui/menu`; сервер сам
  фильтрует пункты по рангу пользователя. Открываются в `PluginActivity` (WebView), токен
  передаётся через cookie `silo_token`, внешние ссылки уходят в браузер.
- **Права.** Проверено: под `user` видны только WebDAV и Showcase, под `owner` - все пункты.
- **Поиск сервера в сети.** `ServerFinder` перебирает адреса подсети и опрашивает
  `/api/system/ping` + `/api/system/version`; в диалоге настроек показывается список найденных
  серверов с версией, выбор подставляет адрес.
- **Иконка приложения** сгенерирована из `Silo/imgs/favicon.png` (адаптивная + legacy-размеры).
- **Экран входа** - компактная карточка по центру (440dp), а не на всю ширину ТВ.

## 10. Итерация 3: иконки, плееры, сортировка/категории

- **Иконка и баннер Android TV** из `Silo/imgs/favicon.png`: логотип вписан в безопасную зону
  адаптивной иконки, отдельно сгенерирован баннер 320x180/480x270/640x360 в стиле Silo
  (тёмный фон, янтарное свечение, надпись SILO + TorrServe). В манифесте `android:banner`.
- **Плееры как в старой версии**: `Players` (список установленных, MIME по расширению, MX через
  компонент `ActivityScreen`, опции «передавать название/постер» на каждый плеер),
  `PlayersDialog` (список с иконками, «Спрашивать каждый раз», «Запомнить выбор»).
  В настройках: плеер по умолчанию и настройки выбранного плеера; долгое нажатие «Смотреть» -
  всегда спросить плеер.
- **Сортировка**: по дате, названию, размеру, скорости (кнопка в заголовке, выбор запоминается).
- **Категории**: фильтр по категории из меню «Категория».
- **«Удалить все»**: удаление всех торрентов пользователя с подтверждением (проверено на тестовом
  пользователе qa: список и сервер очистились).
- **Постеры больше не пропадают**: загрузчик держит старую картинку до загрузки новой,
  кэширует в память и на диск (`cacheDir/posters`), не запрашивает один URL дважды.

Замечание: `PUT /api/torrents/:hash/meta` заменяет мету целиком - при правке только категории
название и постер обнуляются. Восстановлены вручную; клиенту нужно отправлять все поля.

## 11. Итерация 3 (продолжение): меню раздачи, резервная копия

- **Меню раздачи** по долгому нажатию на плитку (мышь/тап) и по кнопке MENU или удержанию OK на пульте:
  «Открыть», «Отметить всё просмотренным», «Копировать ссылку» (torrs:// или magnet), «Удалить торрент».
- **Резервная копия библиотеки**: `.backup/owner_torrs.json` (hash, title, name, category, poster, size, torrs)
  и `.backup/restore.py` - восстанавливает раздачи по ссылкам torrs:// без скачивания метаданных.
  Команда: `python3 .backup/restore.py http://192.168.1.11:8090 owner 123`.
- Проверено на приставке: постеры стабильны (три скриншота через 4 с совпадают),
  «Удалить все» на тестовом пользователе qa очищает и список, и сервер.

## 12. Итерация 4: правки по замечаниям

- **Меню прокручивается**: пункты и плагины в `ScrollView`, бренд и состояние аккаунта закреплены.
- **Плитки не «прыгают»**: данные из REST и SSE сливаются по хэшу (`mergeAll`/`mergeOne`),
  порядок существующих плиток сохраняется; в SSE-карточке нет даты — она берётся из старой.
  Сортировка детерминированная (дата, затем хэш).
- **Выделение как в вебе**: рамку убрали, плитка «всплывает» масштабом (1.05) и тенью,
  и при фокусе пульта, и при наведении мыши.
- **Мета-строка**: у неактивной раздачи только размер; у активной - сиды/пиры и скорость.
- **Бейдж** показывается только для активных состояний (0 добавлен, 1 получение данных,
  2 предзагрузка, 3 работает). Состояния 4 «закрыт» и 5 «в базе» - без бейджа.
- **Карточка торрента**: фокус ставится один раз при открытии и больше не сбивается автообновлением.
- **Предзагрузка перед плеером**: `POST /api/torrents/:hash/files/:idx/preload`, затем ожидание
  `preloaded_bytes > 0` (до 20 с), после чего запускается плеер.
- **Vimu**: передаётся весь список файлов раздачи (`asusfilelist`, `asusnamelist`, `startindex`,
  `forcename/forcedirect/forceresume`) - как в старой версии клиента.
- **Просмотрено**: вместо надписи и иконки play - янтарный кружок справа от файла.

## 13. Итерация 5: вкладки файлов и возврат фокуса

- **Вкладки типов файлов** в карточке торрента: Видео / Аудио / Субтитры / Остальные
  (с количеством файлов). Классификация по расширению; пустые вкладки скрываются.
  Если группа одна - вкладки не показываются, фокус сразу на первую строку файлов,
  если несколько - фокус на выбранную вкладку.
- **Воспроизведение** берёт первый видеофайл (а не первый попавшийся), плейлист для плеера
  тоже собирается из видеофайлов.
- **Возврат фокуса**: при выходе из карточки фокус возвращается на ту плитку, из которой вышли
  (`lastOpenedHash` -> `restoreFocusHash`), а не на первую.
- **Надёжность фокуса**: RecyclerView в рантайме ставит `FOCUS_BEFORE_DESCENDANTS` и забирает фокус;
  принудительно ставим `FOCUS_AFTER_DESCENDANTS` + `isFocusable=false`, а плиткам/строкам файлов -
  `focusableInTouchMode`, иначе после тапов программный фокус не ставится.

## 14. Итерация 6: меню, предзагрузка, окно magnet-ссылок

- **Меню** приведено к порядку: Торренты, Добавить, Удалить все, Категории, Настройки,
  раздел «Плагины», внизу — Донат и Закрыть (бывш. «Выход»). Пользователи переехали
  в Настройки («Сменить пользователя»).
- **Донат** — как в веб: Boosty, YooMoney, T-Bank.
- **Закрыть** — останавливает локальный сервер (если используется) и закрывает приложение.
- **Предзагрузка работает**: `POST /api/torrents/:hash/wake` (активировать сессию в памяти),
  затем `POST /api/torrents/:hash/files/:idx/preload`, затем опрос `preloaded_bytes`.
  Раньше без `wake` сервер молча ничего не делал — отсюда «нет предзагрузки».
  Окно показывает «Загружено X из Y · пиров: N», процент и кнопку «Открыть сейчас».
- **Magnet из других приложений**: окно «Новая раздача» — от чьего имени (пользователи),
  что сделать (Добавить в базу / Просто проиграть / Добавить и проиграть), запомнить действие
  и пользователя. Если запомнено — выполняется сразу без окна. Выбор файла, если в раздаче
  несколько видео/аудио; затем та же предзагрузка и запуск плеера.
  `save_to_db=false` для «просто проиграть».
- **Файлы в карточке**: список обновляется не через `notifyDataSetChanged`, а точечно по id —
  фокус больше не прыгает при обновлении статуса.
- **Навигация пультом**: вниз с вкладки -> сразу в файлы, вверх с первой строки -> на вкладки.
- **Кнопка запуска** показывается и для аудио («Слушать»), а не только для видео.

## 15. Итерация 7: аккаунты, магнет-окно, пиры

- **Предзагрузка**: последовательность `wake` -> ожидание активной сессии -> `preload` -> опрос
  `preloaded_bytes`. Проверено логом: wake=null, active=true, preload=null, preloaded=40 МБ.
- **Пиры везде числами**: «63/64» в карточке, в карточке торрента и в окне предзагрузки.
- **Настройки → Аккаунт**: плашки авторизованных пользователей в строку, нажатие переключает
  пользователя и перезагружает меню плагинов по правам. «Войти под другим», кнопки разнесены.
- **Настройки → Новая раздача**: текущее действие окна добавления и кнопка «Сбросить по умолчанию».
- **Донат**: три кнопки в строку.
- **Окно magnet**: заголовок «TorrServe Silo», имя раздачи (title или `dn`), пользователи плашками
  (последний выбран), порядок действий Играть / Играть и добавить / Добавить, кнопки «Назад» нет,
  фон полупрозрачный — видно приложение, из которого добавлено.
- **Запомненное действие** только подставляется в окно; окно показывается всегда,
  пропустить его можно extra `auto=true`.

## 16. Итерация 8: предзагрузка - настоящая причина

Три независимые проблемы:

1. **Шкала** считалась от размера файла (1,4 ГБ), а предзагрузка 16 МБ -> прогресс ~0,5%,
   визуально «не работает». Теперь шкала = `filled` из `/api/torrents/:hash/cache`
   относительно `preload_size` (16 МБ).
2. **`POST .../files/:idx/preload` падает** с `file index out of bounds: N` - `id` файла
   из `file_stats` не совпадает с индексом в списке файлов движка. Ошибка больше не ломает сценарий.
3. **`preloaded_bytes`** у части раздач остаётся нулём (проверено на The Odyssey: 64 пира,
   cache `filled` = 65 МБ, `preloaded_bytes` = 0). Готовность теперь определяется реальной
   проверкой потока: GET `streamUrl` с `Range: bytes=0-65535`; как только приходят байты -
   запускаем плеер. Это же чтение заставляет сервер подтянуть нужные куски.

Проверено: Heart of the Beast - диалог закрылся за 1,5 с, Vimu открылся; The Odyssey -
65 МБ кэша, `preloaded_bytes` 0, воспроизведение стартует.

## 17. Итерация 9: preload - как в вебе

- `Session.initFiles()` заполняет список файлов только когда у торрента появились метаданные
  (`t.Info() != nil`). Сразу после `wake` список пуст, поэтому `handlePreloadTorrent` отвечает
  `400 file index out of bounds: N`. Проверено curl: 1-я попытка 400, 2-я 200.
- Повторный вызов `preload` перезапускает задачу (`sess.Preload` заново ставит stat=Preload),
  из-за чего `preloaded_bytes` падал обратно и шкала не доходила до конца. Клиент вызывает
  `preload` один раз и повторяет только при ошибке.
- `preloaded_bytes` в статусе = `cache.Filled` (см. `session.go`), то есть ровно то, что
  показывает веб-JSON. Прогресс и готовность считаются по нему относительно `preload_size`.
- Проверка на холодной раздаче: 13,7 МБ -> 26,7 МБ -> 34,6 МБ, stat Preload -> Working.

## 18. Итерация 10: окно выбора как в старом клиенте

Логика взята из `PlayActivity.processIntent()` и `ChooserFragment.show()`:

- `action=play` -> сразу воспроизведение, без окна.
- `action=choose` -> окно даже при включённой галочке (`forceChoose`).
- без extras -> если `savedAction in 1..3`, действие применяется сразу, иначе показывается окно.

Действия: 1 «Играть» (добавить без сохранения), 2 «Играть и добавить» (сохранить в базу),
3 «Добавить» (сохранить и закрыть). В окне галочка «Запомнить» сохраняет выбранное действие.

Исправлен краш: в авто-режиме окно не создаётся, а `setBusy()` обращался к `lateinit` полям.

## 19. Итерация 11: постеры у раздач из NUM

Старый клиент читал extras из intent (`PlayActivity.readArgs()`): `hash`, `title`, `poster`,
`category`, `data`, `fileindex`, `save` - и отправлял их в `POST /api/torrents`.
Наш клиент эти поля игнорировал, поэтому в базе оставался `poster = null` и грузить было нечего.

Теперь `MagnetActivity` читает `title`/`poster`/`category` (регистр ключа не важен) и передаёт
их в `addTorrentEx`. Сервер сам решает, что сохранить. Проверено: magnet с `--es poster ...` ->
плитка показывает постер.

Ответ сервера на вопрос «почему пусто»: своего источника постеров у Silo нет (нет TMDB/Кинопоиска),
мета берётся только из `torrs://` (внутри упакованы title/poster/category) или из extras вызывающего.

## 20. Итерация 12: карточка, общий список файлов, окно magnet

- **Карточка**: верхний заголовок не дублируется (`setHeaderTitle("")`), название у постера -
  `singleLine + marquee`, поэтому длинные имена прокручиваются, а не занимают 4 строки.
- **FilesSection** - общий компонент: вкладки Видео/Аудио/Субтитры/Остальные с количеством,
  пустые не показываются; при одной группе вкладка остаётся подписью (`focusable=false`),
  фокус сразу на списке. Используется в карточке торрента и в окне magnet.
- **Фокус на последний файл**: `Prefs.lastFile(hash)` записывается при воспроизведении,
  запасной вариант - последний файл с `viewed=true`.
- **Окно magnet**: ширина 760dp, список файлов с вкладками и кружками «просмотрено»,
  действия - три плашки (Играть / Играть и добавить / Добавить), выбранная подсвечена.
- **Предзагрузка**: в окне показываются размер файла и скорость; битрейт не выводим -
  сервер не отдаёт длительность, посчитать нечем.

## 21. Итерация 13: память действия отдельно от выбора файла

Проблема: галочка «Запомнить» запоминала действие и полностью пропускала окно, поэтому
у многофайловых раздач нельзя было выбрать другой файл.

Решение: память хранит только действие. Последовательность стала такой:

1. `action=choose` -> полное окно.
2. `action=play` -> действие «Играть», но если файлов несколько - компактное окно со списком.
3. без extras и с запомненным действием -> компактное окно: блоки «От чьего имени» и
   «Что сделать» скрыты, сразу показывается список файлов (если файл один - играем без вопросов).
4. без extras и без запомненного действия -> полное окно.

Проверено на torrs-ссылке с 10 файлами (список появился при запомненном действии)
и на одиночном magnet (сразу окно предзагрузки).

## 22. Итерация 14: окно magnet - две страницы

- Окно разделено на две страницы в одной Activity: `magnet_page_actions` и `magnet_page_files`.
  После «Выполнить» страница действий скрывается, показывается список файлов - окно не разрастается.
- Со страницы файлов убраны прогресс и текст «Выберите файл»; список ограничен 300dp, окно влезает в экран.
- При выборе действия фокус возвращается на выбранную плашку (перестройка чипов + requestFocus).
- Фокус в списке файлов: `prefs.lastFile(hash)`, иначе последний файл с `viewed=true`.
- Просмотр сохраняется на сервере после запуска плеера (`setFileViewed`).
  Ограничение: для «Играть» (save_to_db=false) сервер не хранит запись `user_torrent`
  (`Store.updateUserTorrent` -> `ErrTorrentNotFound`), поэтому отметка не сохраняется.

## 23. Итерация 15: локальный сервер и вход

- Локальный сервер при старте пишет `auth.owner_password` из настроек клиента.
  Пустой пароль -> блок `auth` не пишется, сервер поднимается в режиме
  `Access mode: OPEN (Running as Owner without password)` (проверено по логу).
- Клиент входит сам: `LocalAuth.ensureSession()` логинится как `owner` с этим паролем
  и сохраняет сессию для локального адреса. Вызывать только из фонового потока -
  иначе `NetworkOnMainThreadException` («network error»).
- Порядок в `loadOnce()`: поднять сервер -> дождаться `/api/system/ping` -> войти ->
  прочитать токен -> загрузить список.
- Если вход не удался, экран торрентов пишет «Локальный сервер запущен, но нужен вход…»
  (по нажатию открываются настройки), в меню - «Нужен вход в локальный сервер».
- Порт фиксирован 8090. Если его занял старый TorrServer, наш процесс падает с
  `bind: address already in use`, а приложение общается с чужим сервером (401/404).
